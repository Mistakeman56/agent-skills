# 睡眠时段暂停/恢复定时任务（Tiered Resume）

用户入睡时暂停全部 cron jobs 省 token，起床时分批恢复（因为不同任务的触发时间不同）。

## 场景

用户半夜睡觉（~22:00），早上陆续有不同时间触发的任务：
- **7:00 AM 北京** — 妈妈早安日报（需在 6:00 恢复才能赶上）
- **8:00 AM 北京** — 每日早报 + 余额监控（8:00 恢复即可）

## 分步流程

### 1. 睡前暂停全部任务

```bash
hermes cron pause <job_id_1>
hermes cron pause <job_id_2>
hermes cron pause <job_id_3>
```

### 2. 创建一次性恢复任务（按时间线）

**6:00 AM 恢复妈妈日报：**
```bash
hermes cron create "6点恢复妈妈早报" \
  --schedule "2026-05-13T22:00:00Z" \
  --deliver origin \
  --prompt "现在北京时间早上6点。请把妈妈早安日报任务 (25d4e3659f36) 恢复（resume）。另外两个任务保持暂停。"
```

**8:00 AM 恢复其余任务：**
```bash
hermes cron create "8点恢复其余任务" \
  --schedule "2026-05-13T00:00:00Z" \
  --deliver origin \
  --prompt "现在北京时间早上8点。请把每日早报 (a1d1d1ef7372) 和 DeepSeek 余额监控 (125b71ecb4da) 恢复（resume）。妈妈早报已在6点恢复，不要动它。"
```

> 8:00 AM 北京 = UTC 00:00，6:00 AM 北京 = UTC 22:00（前一日）

### 3. ⚠️ 关键：恢复时间必须提前于触发时间

**如果恢复任务和目标任务在同一时间运行，目标任务会错过窗口期。**

例如：每日早报调度在 8:00 AM（`0 0 * * *` UTC），如果恢复 cron 也设在 8:00 AM，则：
1. 8:00:00 — 恢复 cron 执行，resume 每日早报任务
2. 8:00:00 — 每日早报的调度窗口已经在这一秒过去了
3. 下次调度变成明天 8:00，今天的简报漏了 ❌

**修复方案**：恢复 cron 的调度时间要提前至少 **5 分钟**：
- 7:55 恢复 8:00 的每日早报（`0 0 * * *` → 恢复在 `2026-05-12T23:55:00Z`）
- 6:00 恢复 7:00 的妈妈日报（`0 23 * * 0-4` → 恢复在 `2026-05-12T22:00:00Z`，这个已正确）

### 4. 注意事项

- 一次性任务（`repeat: 0`）跑完即消失，无需清理
- 恢复任务的 prompt 中**必须显式指定 job_id**（不是靠名字匹配），因为 cron session 是独立的，没有对话上下文
- 每个恢复任务只做自己的事（不碰其他任务），避免竞态条件
- 如果妈妈日报 7:00 发不出去（微信限流等），需要先修好再让 cron resume

### 4. 第二天醒来

用户 8:00 醒来时，全部任务已恢复：
- 7:00 妈妈收到了早安日报 ✅
- 8:00 每日早报 + 余额监控恢复正常 ✅
- 所有任务在睡眠期间（22:00~6:00）零消耗 ✅
