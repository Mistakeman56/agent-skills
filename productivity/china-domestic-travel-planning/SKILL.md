# 中国国内旅行规划

当用户要去国内多城市旅行（如上海-苏州-杭州），需要查机票/高铁价格、选酒店区域、分配预算时使用。

## When to Use

- 用户给出已订的机票/酒店/车票，问剩余预算怎么花
- 查某天某航线最低价、某天某段高铁车次
- 推荐某城市住哪个区域（靠近景点/地铁）
- 编制多人（通常是2人）多天行程 + 预算分配表

## 工作流程

1. **表格化已定行程** — 把用户已订的票/酒店整理成表格（日期|事项|状态），标出还没定的（返程机票、中间段高铁、末段酒店）
2. **确认天数与人数** — 7天/2人等，预算口径（总预算还是人均）
3. **并行查询待定项价格**（见 references/transport-apis.md）：
   - 返程机票：携程 lowestPrice API，一次返回未来2个月每日最低价
   - 城际高铁：12306 queryG API（需先取 cookie）
   - 末段酒店：高德 MCP maps_text_search 查目标区域连锁酒店
4. **编制预算分配表** — 固定支出（机票/高铁/酒店）逐项扣除，剩余金额 ÷ 天数 = 每日可花；给出吃饭/景点/市内交通的分配
5. **给出风险提示** — 机票越晚越贵要赶紧买；高铁票提前买

## 预算分配模式（2人）

```
剩余预算 - 返程机票×2 - 城际高铁×2 - 末段酒店 = 每日可用
每日可用 ÷ 剩余天数 = 每天花费上限
经济型参考：吃饭人均50-60/天，景点按门票累加，市内交通地铁为主
```

**例（2026-08 上海-苏州-杭州 7天2人）：** 剩3600 → 机票900 + 高铁230 + 酒店250 = 剩2220 → 每天约317元

## 酒店区域选择（高德 MCP）

用 `maps_text_search(keywords="汉庭酒店 西湖", city="杭州")` 查目标区域连锁酒店：
- 优先地铁站步行500米内、近主要景点
- 连锁品牌（汉庭/亚朵/如家）价格稳定、质量可预期
- 用 POI 的地址和地铁描述判断便利性

## Pitfalls

- **⚠️ 查具体航班号/时刻 = 无鉴权不可行，直接让用户开APP（2026-08 实测）**：当用户问"那个便宜航班具体是哪班/几点起飞"时，JSON API 只给最低价不含航班详情，而所有浏览器渠道全被挡：携程432/whaleguard、春秋官网需登录(passport.ch.com)、去哪儿404、天巡captcha、飞常准502、百度验证码。**不要逐个试**（会浪费十几轮工具调用），直接报价+说"具体航班在携程/春秋APP按价格排序看，最低价那班就是"。春秋去程是9C8978时，回程低价票大概率也是春秋。
- **⚠️ 专门的爬虫 MCP 也打不破携程反爬（2026-07 实测）**：曾部署 FlightTicketMCP（DrissionPage 爬携程）到 CT <ID> 想解决"查具体航班号"——手机 UA + 反自动化标记全部无效，机房 IP 被 whaleguard 识别返回空页面。**不要指望部署爬虫 MCP 绕过**，机票详情就靠用户 APP。该 MCP 的天气/航班动态功能可用（见 pve-administration 的 mcp-server-deployment-ct200.md）。
- **⚠️ 12306 返回的车次必须校验实际上车站！2026-08 用户当场抓到错误**：用 `queryG(from=SZH, to=HZH)` 查苏州→杭州，返回 195 个车次看似全对，但**相当一部分车次的上车站根本不是苏州站**——12306 会返回整条走廊的车次，`[6]` 可能是 盛泽/苏州南/苏州园区/张家港/太仓/常熟 等周边站（例：G3309 上车站=盛泽，用户看到后直接质疑\"途径站也没有苏州啊\"）。**必须用 station_name.js 把每条车次的 `[4]始发 [5]终到 [6]上车 [7]下车` 都翻译成中文站名，只推荐 `[6]==目标站` 的车次**，并在回复里明确标注上车站（\"苏州站上车，不是苏州南/盛泽\"）。字段索引见 references/transport-apis.md。
- **⚠️ 浏览器/网页全被反爬挡**：携程 flights.ctrip.com 返回 432，12306 需要验证。不要反复试浏览器，直接用 JSON API（见 references/transport-apis.md）
- **12306 必须两步**：先 GET `/otn/leftTicket/init` 存 cookie，再 queryG 才有数据；直接 queryG 返回 `{"status":false}`
- **价格是"最低价"不是"该航班价"**：lowestPrice 返回的是当日该航线最低价（多为春秋/九元等廉航），不是所有航班均价。口头报价要说明"最低价"口径
- **机票临期涨价**：8月初旺季，8/11 450元的低价票不会等人，建议当天就下单
- **预算口径要问清**：3600 是总预算还是人均？两人均分要主动说清楚
- **⚠️ 大众点评"人均"可能被同址平价档口拉低（2026-08 用户当场抓到）**：人和馆（静安寺店）显示人均40，实为 1 楼面馆/点心/外卖档拉低，3 楼正经本帮菜人均 176-250。**推荐餐厅前必须核对网友推荐菜 + 真实食记**（吃了什么/花多少），回复里报"官方显示X / 实际点菜人均Y"两个口径——用户会自己上大众点评核对，口径不清会被质疑
- **⚠️ 行程进行中安排"明天玩什么"前，先确认这趟已去过哪（2026-08 用户当场纠正）**：用户在上海已玩过豫园/城隍庙/外滩/陆家嘴，我却按"经典一日游"推荐了豫园城隍庙，用户直接纠正"你理解错了，我们已经去过了"。行程中途排次日计划时，**先问/先查这趟已打卡了哪些**，再推互补路线（已看摩登夜景→推法租界梧桐区 Citywalk），别推重复景点
- **⚠️ 台风季（7-9月）先问清用户出行/航班日期再判断影响（2026-08 实测）**：用户问"杭州航班会不会被台风影响"时，先确认是哪天——用户说8/13而非我以为的8/11，日期差3天结论完全不同（8/9-10台风登陆日航班高概率停运，8/13台风已消散只留小雨不影响）。台风路径看中央气象台 typhoon.nmc.cn；注意"双台/三台共存"（8月常有三台共舞，各台风路径都要查）；高铁停运12306自动退票（5日内免手续费），联程票要手动一并退，**停运后马上重买次日车次**（台风登陆次日凌晨起铁路陆续恢复，选上午班次），并通知目的地酒店改期、原酒店续住。详见 references/hangzhou-guide.md。
- **⚠️ 具体门店（餐厅/酒吧/足疗/按摩）推荐前必须验证真实存在性（2026-08 用户两次抓到错误）**：SEO营销软文网站（51xxsp / zuyu123 / v7x9 / laibinjy 等聚合站）会**编造门店**——"渝富桥足浴苏州观前街店"实际不存在（渝富桥是成都品牌，江苏加盟店在张家港锦丰镇），用户当场搜不到；"罗斯福色戒酒吧"用户现场也找不到。**推荐具体商家前，用 Exa 搜索 + 360地图/大众点评 POI 交叉验证真实存在**（Exa 直接索引地图 POI，比默认 web_search 返回的营销软文靠谱得多）；连锁品牌的加盟分布要在加盟官网查证。**酒店内酒吧/餐厅永远比街边网红店稳**（茂悦非常时髦/和平饭店9:15露台/艾迪逊ROOF 官网常年可验证）。用户明确要求"你咋不用exa搜"——**查门店、商家、攻略、当地特色一律先用 Exa SDK（venv 里 exa_py）直查，别用默认搜索**

## 用户出行偏好（assistant，2026-08 实测确认）

排行程和查票时**默认按这些偏好来，不用问**：

- **🚄 高铁选中午以后的班次**：用户明确说过"不行，这个太早了，给我挑一个中午以后的"。推荐 12:00-15:00 出发的车次，别推早班车。配合酒店退房（一般12点前）正好。
- **🛏️ 下午必须留休息时间**：行程模式是"上午景点 → 中午吃饭 → **下午回酒店午休/点外卖** → 傍晚再出门看夜景"。8月城市高温，中午2-3点安排户外活动是受罪，用户自己就是这么排的。
- **🌃 夜景是行程重点**：外滩/东方明珠/山塘街这类夜景体验用户很看重，晚上时段要排足。
- **💰 两人出行、预算敏感**：推荐项目要带价格（门票/人均），主动算总预算；贵的体验（如登塔¥220/人）主动建议"只拍不登"省钱。
- **🍽️ 餐厅/美食推荐给多个选项，别只推一个（2026-08 外滩实测）**：用户明确说过"你多推荐几个，这一个太少了"。推荐饭店按风格分层给 4-6 个（本帮菜/西餐/小吃/高档，各带人均和特点），结尾给 1 个最优建议 + 问预算收口。"给1个最优方案"只适用于炒股/行动类决策，休闲餐饮要菜单式推荐。外滩餐厅速查见 references/bund-night-guide.md。
- **🏨 连锁酒店（汉庭等）优先**：地铁步行500米内、近景点，价格稳定可预期。

## 行程/攻略做成图片（两种方式，用户会交替要求）

用户会要求"整理出来做成一张图片"（如杭州3日攻略、上海Day2攻略）。**有两种方式，2026-08 实测：**

### 方式A：HTML + playwright 截图（新版，用户本session指定\"用html然后再截图发我\"）
写一个 `1080px` 宽的 HTML（Noto Sans CJK 字体、时间线卡片布局、emoji 可用），用 playwright 无头截图：
```python
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch(headless=True, args=['--no-sandbox','--disable-gpu'])
    pg = b.new_page(viewport={"width":1080,"height":1400}, device_scale_factor=2)
    pg.goto("file:///tmp/guide.html", wait_until="networkidle")
    pg.screenshot(path="/root/guide.png", full_page=True)
    b.close()
```
- **HTML 方式能用 emoji**（PIL 不能），排版更灵活漂亮，用户接受度高
- `device_scale_factor=2` 出高清图（微信里放大清晰）
- 模板：`templates/guide-html-template.html`（上海Day2时间线卡片样式，可直接改内容复用）

### 方式B：PIL + Noto CJK（旧版，仅当无 playwright 时）
`scripts/generate_travel_guide_image.py` 是可复用模板（米白底+西湖绿配色卡片，动态高度，已验证可出图 1080px 宽）。

**⚠️ PITFALL: PIL 不渲染 emoji！** Noto CJK 字体没有彩色表情，`🏞️`/`🌅` 等会显示成空白/方框。用户看到会直接说"表情没显示出来"。**全部用 `◆`/`·`/`|` 等纯文本符号替代 emoji。**

**⚠️ PITFALL: 固定画布高度会截断内容！** 中文卡片内容多，先定 `Image.new((W, 2000))` 再画，底部（返程/预算/提醒）会被裁掉，用户会说"返程那块有遮挡"。**必须两遍法：先用 `d.textlength()` 估算每张卡片高度累加出 total_h，再 `Image.new((W, total_h))` 正式绘制**，最后 `img.crop((0,0,W,y+10))` 收尾。描述行可能换行，估算时按 `textlength > max_w` 判断行数。

**关键代码：**
```python
FONT_REG = "/usr/share/fonts/noto-cjk/NotoSansCJKsc-Regular.otf"   # 服务器已有
FONT_BOLD = "/usr/share/fonts/noto-cjk/NotoSansCJKsc-Bold.otf"
def draw_wrapped(d, x, y, text, fnt, max_w):   # 逐字换行绘制
    lines, cur = [], ""
    for ch in text:
        if d.textlength(cur + ch, font=fnt) > max_w and cur:
            lines.append(cur); cur = ch
        else:
            cur += ch
    lines.append(cur)
    for ln in lines: d.text((x, y), ln, font=fnt); y += fnt.size + 8
    return y
```
验证：`browser_navigate(file:///root/xxx.png)` 后 `browser_console` 查 `naturalWidth/Height`；当前主模型无视觉，别依赖 vision_analyze（看图内容用 image-analysis 技能的 Kimi 视觉兜底）。
