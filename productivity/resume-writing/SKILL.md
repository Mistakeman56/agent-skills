# 简历/项目经历写作(the user)

## 规则（每次都适用）
1. **形态二选一，不混排**：① 单段到底，段内用加粗分层引导词按 **网络层→平台层→应用层→代表案例** 递进；② 按同一分层拆 bullet，每层一组。交付时附一行「结构说明」解释为什么这么排（给自己校对用，不当正文交）。
2. **量化先行**：每个能力点带数字（带宽、实体数、日志行数、工具数、7×24）；给不出数字的能力点降级或删。
3. **开源角色红线**：开源项目一律写「自托管部署 + 深度配置 + 场景构建」，禁「自研/独立开发 XX」——面试追问底层即露馅。
4. **题材措辞红线**：代理/翻墙类只写「分流网关、策略路由、透明代理」；不出现「机场、翻墙」及翻墙用途描述。
5. **AI 经历展开写**（他明确要求）：Hermes 中枢按「入口(IM)→工具/MCP→混合模型→自治任务→harness 编排」展开；Claude Code / Codex / DeepSeek Harness(dsh) 列为三大模型阵营的统一编排，叙事是「按任务分发到不同生态」，不是罗列工具名。
6. **案例收尾留记忆点**：挑一个具体到反常的细节（如「数据文件里存着 404 错误页」），并按 STAR 备讲。
7. **交付节奏**：先给文字稿等确认再排版 docx；docx 必须 100% 匹配模板格式（字体/数字格式/边框/合并单元格/列宽行高），默认先列修改清单再动手。

## 步骤
1. 盘点素材：记忆中的 Home Lab / 网络 / AI 资产 + 本次会话新事实。
2. 按规则 1 选形态起草。
3. 自检：数一遍量化词；扫描红线词（自研/翻墙/机场）；逐条问「面试能否讲出设计动机、坑、解法」。
4. 输出文字稿 + 结构说明，再问是否需要排版。

## Pitfalls
- **harness ≠ 模型**：Claude Code / Codex / dsh 是 harness，模型分属 Anthropic / OpenAI / DeepSeek 阵营；dsh（DeepSeek Harness）仍是 v0.1 预览，写「纳入编排评估」，别写「生产依赖」。
- **别把角色写小**：「部署 + 配置 + 验证 + 工程化场景」就是他的真实角色与卖点，虚报反而毁掉可信度。
- 面试官只看第一遍：每个 bullet 都要能独立讲出故事，堆砌关键词的条目直接删。
