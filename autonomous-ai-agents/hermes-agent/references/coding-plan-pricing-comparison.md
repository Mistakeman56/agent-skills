# 国内 AI Coding Plan / Token Plan 订阅对比

基于 2026 年 5 月各厂商官网 + 实际 API 测试数据的整理。

## 核心差异：三种计费模式

| 模式 | 代表厂商 | 本质 |
|------|---------|------|
| **Token 计费** | Kimi Code, MiniMax | 按实际 token 消耗扣减，带缓存折扣 |
| **Credit 点数** | 小米 MiMo | Token 按比例折算为 Credit，长上下文有惩罚倍数 |
| **Prompt 次数** | 智谱 GLM, 阶跃星辰 | 1 prompt ≈ 15-20 次模型调用，额度不透明 |

## 各平台详情

### Kimi（月之暗面）— 统一积分制

核心模型 Kimi K2.6（1T MoE，支持推理+多模态）。2026年5月起升级为**统一积分（Credit）系统**，Agent、PPT、Kimi Code、Kimi Claw 等功能共享同一积分池，按实际使用扣减。

**注意：Kimi API（api.moonshot.cn）上 kimi-k2.6 的实际上下文为 256K，并非 Kimi Code 产品宣传的 1M。Hermes 这类 agent 框架通过 API 调用时受 256K 限制。**

| 套餐 | 月付 | 年付（每月） | Agent 次数/月 | Kimi Code 积分 | 专业数据请求 | 并发任务 |
|:----|:---:|:----------:|:------------:|:-------------:|:----------:|:-------:|
| 入门 | **¥49** | ¥39 | 6 | 1x | 200 | 1 |
| 标准 | **¥99** | ¥79 | 30 | 4x | 1000 | 1 |
| 专业 | **¥199** | ¥159 | 60 | 20x | 2000 | 2 |
| 旗舰 | **¥699** | ¥559 | 360 | 60x | 5000 | 4 |

**Kimi Code 积分倍数说明**：1x ≈ Kimi 月度套餐中包含的基础 Kimi Code 调用额度（未公开具体 token 数）。4x = 4 倍基础额度。

**适用场景判断：**
- ¥49 入门级：适合轻量使用，6 次 Agent 调用/月对于 Hermes 场景偏少（我们一天就 11 轮 API 调用）
- ¥99 标准级：目前用户使用的套餐，体验反馈"很耐用"
- ¥199 以上：需要 2x 并发或大量专业数据查询的重度用户

**⚠️ 重要提示：Kimi 会员积分 ≠ Kimi API（api.moonshot.cn）的 token 配额。** 会员积分主要用于 Kimi 平台内（网页端、Kimi Code、Kimi Claw）的消费。通过 API key 调用 kimi-k2.6 走的是独立的 API 计费体系，需确认账户是否有 API 额度或余额。

### 小米 MiMo Token Plan — ¥39 Lite

核心模型 MiMo-V2-Pro（MoE，上下文规格未公开）

| 特性 | 详情 |
|------|------|
| 价格 | ¥39/月（Lite） |
| 计费 | **Credit 点数体系**，token → credit 按比例折算 |
| ⚠️ 长上下文惩罚 | **处理 >100K 上下文时，1 token = 4 Credits** |
| 刷新 | 月度固定额度，**无 5 小时窗口，无周刷新** |
| 实际可用 | 标称 ¥39 的额度在长上下文场景下仅相当于 **¥9.75** |
| 结论 | "非常不耐用"——Lite 档额度低 + 长上下文 4 倍扣 = 重度用户一天见底 |

**核心坑：这个 Credit 体系对所有终端代理场景（OpenClaw/Hermes/Claude Code）天然不友好——system prompt 本身就 >40K tokens，每次调用都在长上下文区间。**

### 智谱 GLM Coding Plan — ¥49 Lite / ¥149 Pro

核心模型 GLM-5.1（744B/40B MoE）+ GLM-5-Turbo

| 特性 | Lite (¥49) | Pro (¥149) |
|------|-----------|-----------|
| 每 5 小时额度 | 80 次 prompt | 400 次 prompt |
| 高峰期倍数 | GLM-5.1 **3 倍**扣额度 | GLM-5.1 **3 倍**扣额度 |
| 非高峰期倍数 | GLM-5.1 2 倍 | GLM-5.1 2 倍 |
| 限时福利 | — | GLM-5-Turbo 非高峰期 **1 倍** |
| MCP 额度 | 100 次/月 | 1000 次/月 |
| 适合人群 | 轻量尝鲜 | 中重度，但注意高峰期倍数 |

**注意：按 prompt 次数计费而非 token，额度透明性差。高峰期（14:00-18:00）调用旗舰模型按 3 倍扣额度很伤。**

## 选购建议

| 你的模式 | 推荐 | 理由 |
|---------|------|------|
| 重度日常编码 | **Kimi ¥99** | 周+5h 双刷新 + 1M 上下文不惩罚 + 多模态 |
| 轻量尝鲜 | GLM ¥49 | 每 5 小时 80 次，够轻度使用 |
| 预算有限 | 避开小米 ¥39 | 长上下文 4 倍扣，实际成本反而更高 |

## 小米 MiMo 避坑说明

小米 MiMo Token Plan 的设计对**短文本对话**场景是合理的（1 token = 1 Credit），但对**终端代理场景完全不适合**：

**⚠️ API 架构限制：Token Plan API 没有余额查询端点。** `token-plan-cn.xiaomimimo.com` 是纯 OpenAI 兼容代理，不提供 `/v1/dashboard/billing/usage` 等余额接口。平台管理 API（`platform.xiaomimimo.com`）需要小米账号登录，API Key 不认。因此无法通过脚本自动监控剩余额度。详见 `references/mimo-token-plan-api.md`。
- 每次调用需要加载 40K+ tokens 的 system prompt（工具描述 + 上下文）
- 这 40K 全在长上下文区间 → 4 倍扣 Credit
- 再加上模型输出 token，单次调用可能消耗标称的 5-6 倍
- ¥39 Lite 套餐在 Coding Plan 场景下的实际可用次数 ≈ **其他家 ¥10 以下的水平**
