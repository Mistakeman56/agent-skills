# 消费科技简报 (Consumer Tech Briefing)

cc常抛的"科技闲聊"类问题：某场发布会怎么样、DeepSeek 新模型升级了啥/排第几、iPhone 某代为什么跟别的版本不一样、某产品值不值得买。**这类问题看着像聊天，他要的是有事实、有观点、有结构的答案**——不是复述官网通稿。

## 何时触发
- "如何评价 XX 发布会？打多少分" / "XX 升级了啥 / 现在排名多少"
- "为什么 XX 和别的版本不一样" / "值不值得买 / 对比一下"
- 市场/产业类预测："XX 什么时候见顶/降价"、"某厂商能不能打破垄断"、"现在该不该买硬件" → 见下「市场/产业预测类」
- 品类：Apple/iPhone、DeepSeek 等国产大模型、小米、外设、消费电子、存储/显卡等 PC 硬件

## 标准流程
1. **先确认"是哪一个"** —— 用户常省略时间/型号（"这次发布会""这个模型"）。**先查证日期与事件再回答**，别默认最近一场就动手。
   （教训：用户说"这次苹果发布会"，实为 2026-09-10 特努斯首秀场，先搜索才定位到。）
2. **多源检索**（后端用 Exa，用户指定）：
   - 一手事实 → 官方 newsroom / 官网新闻稿
   - 现场细节 → 新浪科技、36氪、TechCrunch、Wired、Reuters、MacRumors
   - 排名 → LMArena、Artificial Analysis 等第三方榜单
3. **区分"厂商自报"与"独立验证"**：
   - 厂商 benchmark 跑分 = **自报**，措辞写成"官方打榜成绩"
   - 独立榜单排名 = **有滞后**。新模型/新产品刚发布时榜单尚未收录是常态 → **必须如实说明**，绝不能把旧版本排名安在新版本头上。（教训：V4.1 Flash 发布当日 LMArena/AA 仍只有 V4 Pro/Flash 旧数据。）
4. **结构化输出**：事实进表格，观点用分点，末尾给结论/建议。中文，标题分级。

## 打分 / 评价类（用户明确要分数时）
- 要"1~100 分"就**给一个明确的单一数字** + **分维度加权明细表**，不要只给模糊评价。
- 可复用维度：创新突破 / 产品力 / 定价 / 生态软件 → 分项得分 + 合计。
- 输出骨架：`发布内容总览表 → 加分项 → 减分项 → 评分明细表 → 一句话总评`。
- **敢下判断**，例如"创意85 / 诚意70 / 价格60 / 综合73"。
- 结尾主动给下一步：整理成图 / 建议等二代 / 与竞品对比。

## 市场/产业预测类（价格周期、"某厂商能否破垄断"）

这类问题问的是"这说法对不对"，但 the user 真正要的是**决策**（现在买还是等）。骨架固定：

1. **先拆含糊口径** —— "最高值/见顶"至少三义，必须分别答再合并：① 绝对价格见顶 ② 涨幅速度见顶（往往早已发生）③ 性能/性价比见顶。只答一种口径 = 答非所问。
2. **多机构时间线表** —— 列 5–8 家（TrendForce / 摩根士丹利 / UBS / IDC / Counterpoint / 厂商自己）的判断时点，**标出中位数共识 vs 尾部情形**；把某个说法定位成"乐观的 25 分位"比直接否定更准确。
3. **单列"降 ≠ 回到从前"这类关键前提** —— 如价格回落但底价永久抬升 X%；不写这条，用户会按旧锚点做计划。
4. **打分**（同上一节：单一数字 + 维度明细表）。
5. **落到实操** —— 结尾必须给"现在买 / 该等 / 别赌"三档结论 + 触发时间点；纯评论算没答完。

⚠️ 两条最容易犯的错：
- **不要把"某国产厂商崛起"直接推成"价格会降"** —— 拆成两个命题分判：① 能否打破垄断（份额/进供应链就是事实答案）② 能否压价（看它的成本结构、有无价格战弹药、产能是否被长协锁死、它自己是否已是涨价受益方）。二者结论经常相反。
- **不要用"历史上崩过盘"替代当前主线判断** —— 尾部情形要标明是尾部，不能拿它当基准预测让用户据此定计划。

## 选购/推荐类（"给我找个好用的 X"，带"得准/得有用"这类硬要求时）

1. **先定失效场景，再谈参数**。把候选功能逐条问"这功能在他的场景里什么时候真的起作用"——换个场景价值就归零（宠物定位：户外走丢 → 卫星是主力、WiFi 定位没几个热点可用；被人关在室内 → 卫星被墙挡死，WiFi/蓝牙/扫码牌反而成了救命稻草）。**用户第一次反驳"这功能在我这儿没用"时直接翻转排序**，不要守着原榜单辩护。
2. **推荐前验"买得到"**：给主流渠道（京东自营/天猫）实测券后价 + 可点链接；榜单第一不等于好买，冷门型号直接降档。用户贴的搜索截图要**先核对 SKU 是不是同类商品**——同品牌的几十块"识别项圈"往往根本没有电子定位，照着截图比价会比错品类。
3. **必须给黑名单**：列出该品类的营销话术（"5G定位/0误差/98星"）与已知翻车类型（纯蓝牙靠众包、基站 LBS 误差几百米、无地理围栏），用户才知道为什么排除谁。
4. 输出骨架：`场景结论 → 分档推荐表（价格/续航/实测误差/渠道）→ 黑名单 → 下一步（要不要我实时比价）`。

## 用户偏好（务必遵守）
- 喜欢**表格 + 攻略图**；萌系语气可以，但"干正事的靠谱程度一点没变"。
- **米粉**：讲手机/智能家居时，自然带一句与小米或国产竞品的对比视角。
- 技术强、爱先调研再决策 → 给事实、给取舍，别空喊。
- 价格敏感（性价比党）→ 涨价、减配、缺失版本都要点出来。
- 第一代新产品（首代折叠屏等）→ 提示"试验品、等二代再冲"。

## 常见坑
- ❌ 把省略的型号当成最近一款就答 —— 先搜证。
- ❌ 把厂商跑分当成独立榜单排名 —— 必须区分并标注。
- ❌ 给新发布产品下"排第几"的硬结论 —— 榜单滞后，如实说。
- ❌ 只夸不批 —— 用户要真实评价，槽点/取舍/涨价都要写。
- ❌ **拿同一指数的不同版本分数排名次** —— 榜单指数会改版，同名分数跨版**不可比**。比两个产品的分之前先核对指数版本号；版本不同就只能各自标注"XX 于 vA 得 N 分"并明说"跨版不可比"。厂商通稿最爱拿自家新版本分数压对手旧版本分数，照单全收就会写出假结论。
- ❌ **只比标价就下"便宜/贵"** —— API/订阅类产品要按**负载结构**算：缓存命中 / 未命中 / 输出三档分别计价，再套真实用量（agent 场景命中率 85%+、系统提示占输入大头）估出"每轮 / 每月"实际数再比。标价便宜 3 倍但输出贵 2 倍的产品，在重输出负载下反而更贵。还要写清**冷启动 / 刚换模型那一轮会特别贵**（整段前缀未命中）这种非典型成本，否则用户按稳态数做预算会超。
