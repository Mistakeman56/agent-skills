# 热点事件查证与点评

the user 常抛"**如何评价 XXX 事件**"——网红翻车、网络争议、社会舆情；也会发来一条自媒体图文/短视频截图问“**验证信息真假**”。两种都要的是**先核实、后有观点、有结构、敢下判断**的答案，不是复述营销号。**先查证再评价是硬规则**：查不到就直说查不到，绝不凭印象编造。

（同类技能：科技产品/发布会/新模型类问题走 `consumer-tech-briefing`；本技能管**非产品的热点事件与网络争议**。）

## 何时触发
- "如何评价 / 如何看待 <事件>"、"这事到底怎么回事 / 为什么越闹越大"
- 用户发来**截图/链接**问"这是真的吗 / 验证信息真假 / 帮我查查"（尤其是医药健康类“新药要来了”、转发式“好消息”）→ 走下面的**模式二**
- 用户补一句"**他 X 号又回应了你再看看**" → **必须重新检索最新进展**，不能只复述上次结论
- 网红/直播/连麦事件、行业舆情、社会热点

## 标准流程
1. **多角度检索定位事件**：中文关键词 + 时间 + 涉及方（人名/店名/平台）。至少 **2 个独立来源**。
2. **当天/极新的热点：搜索索引会滞后** → 别只靠 `web_search`。直接去平台按时间搜：
   - B站：`https://search.bilibili.com/all?keyword=<关键词>&order=pubdate`
   - **切片账号的视频标题本身就是直播内容的准确摘要**（例："突发！再回应17小时事件，勇哥：你有本事再说一句试试"），比新闻稿更快、更细。
3. **要"原话/实录"** → 虎扑、贴吧、知乎的文字记录帖（连麦原话实录最可靠；本次靠虎扑实录还原了 17 小时连麦逐句对话）。
4. **行业/商业事件** → 红餐网、网易、36氪、游民星空等的转载与分析文；注意区分原发与二次转载源。
5. **交叉验证**：时间、数字、涉事方至少两源一致才当实锤；单源或切片标题可能夸张 → **明确标注**"（切片标题，可能带夸张）"。
6. **交卷前自查**：有没有把"听说"当"事实"？有没有编造细节？

## B站检索代码（cloakbrowser MCP）
抽取搜索结果卡片（标题 | UP | 时间 | 链接）：
```js
(() => { const els=[...document.querySelectorAll('.bili-video-card')];
  return els.slice(0,60).map(e=>{
    const t=e.querySelector('.bili-video-card__info--tit')?.innerText||'';
    const a=e.querySelector('a')?.href||'';
    const up=e.querySelector('.bili-video-card__info--author')?.innerText||'';
    const d=e.querySelector('.bili-video-card__info--date')?.innerText||'';
    return t+' || '+up+' || '+d+' || '+a;
  }).join('\n'); })()
```
**别指望从 B站视频页抓到正文**：页面里的"简介"多是同账号合辑列表，评论区是懒加载（滚动后也常为空）。事实要用**标题目录 + 其他文字源**拼。

## 浏览器通道（优先级）
1. `browser_exec` —— 需本机有 Chrome 在运行。若报 `browser-harness: daemon default didn't come up` 或 `chrome-not-running`，**不要恋战**。
2. **cloakbrowser MCP** —— 已验证可用的备用通道：`browser_navigate(url)` → `browser_evaluate(script=JS)` → `browser_snapshot()`。查 B站/中文平台页面走这条即可拿到内容。

## 模式二：单条信息的真假核验（"验证信息真假"）

用户发来一条短视频截图 / 自媒体图文 / 群里转发的"好消息"，问"这是真的吗"——他要的不是事件点评，是**逐条判真假**。

1. **拆条**：把帖子里的**每一条可验证陈述**列出来（**标题也算一条**），一条不落。
2. **逐条判定**：✅ 真 / ⚠️ 半真（含张冠李戴、过度乐观）/ ❌ 假 —— 每条后面挂**依据**。
3. **给干净版的真实进展**：把被缝在一起的东西**分开列**——谁做的 / 到底是什么 / 到哪一步 / 什么时候，用表格。
4. **补最新进展行**：媒体信息常滞后于官方公告，去查最近一期官方公告（药企/监管/学术期刊）。
5. **给识别筛子（≤3 条，可复用）**：有没有关键期临床/审批？谁发的（机构·官媒 vs 保险号·带货号·科普号）？底部有没有挂**直播预约/卖东西**？
6. 收尾：一句金句式判断 + 一条点到用户自身的落地建议。

坑（都会重复遇到）：
- ❌ **真碎片拼出假期待**：假消息很少凭空编，常用真 A + 真 B 缝成假 C（"真有一个在研疫苗" + "真有半年一针的长效降压针" = 假的"明年就能打一针不吃药"）。所以**不要因为某条真就整体采信，也不要因为整体夸大就判纯假——逐条切分**。
- ❌ **把"公司目标/研究者期望"当上市时间表**："预计某年上市"是目标不是结论。顺手查这个项目**历史上有没有被说过某年上市然后延期**，有前科就把年份整体降权。
- ❌ 引用**二手媒体转述**的临床数据（存活率、样本量）却不标"未核到原文"。
- ❌ 把**食品/保健品**当治疗：同一研究者监修的宠物粮 ≠ 他的注射药（"防火"≠"灭火"）。
- ✅ **真的那条要明确标真**——用户想知道哪些能信，不是只想知道哪里假。

## 输出骨架（用户偏好，已在多轮验证）
1. **事实还原** —— 原话/数字/时间先摆平（能引原话就引原话）。
2. **分层拆争议** —— 例：事实层 / 方法论层 / 姿态层；或 法律 / 情理 / 底线。
3. **核心观点** —— 一句金句式总判断（"不是 X，是 Y"）。
4. **打分表** —— 维度 × 分数 + 理由，总分 **/100**，**要敢给明确数字**。
5. **落地启发** —— 一句话点到用户自身（他在搞盒子副业/当"小老板"，可点一句）。
6. 来源与不确定处明确标注。

- 用户追问进展 → 给**"更新版"**：补时间线 → 新增内容 → **更新打分并写成区间变化**（例：32 → 35），并说明为什么变。

## 常见坑
- ❌ **凭印象评价未核实的事件** —— 先查证；查不到直说。
- ❌ 只搜一次就下结论 —— 当天热点索引滞后，必须去平台按时间搜。
- ❌ 把切片标题/营销号当实锤 —— 标注不确定性。
- ❌ 用户追问后仍复述旧结论 —— 必须重新检索最新进展（本次 9.10 那场就是靠 pubdate 才找到的）。
- ❌ 一锅乱炖式点评 —— 把议题**拆开逐个评**：同一事件里他可能"这条错、那条对"（如"17小时是否违法"扣分、"不许网暴家人"加分）。
- ❌ 只批不谅 / 只夸不批 —— 用户要真实评价，两边都要写。
