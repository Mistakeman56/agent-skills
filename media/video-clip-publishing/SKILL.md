# 直播切片 / 视频自动投稿流水线

## 触发
- "自动直播切片"、"把长直播/录播剪成小视频"、"AI 做封面标题一条龙发 B站"
- "本地部署模型跑视频工作流"、"搬运外网博主内容"、"素材批量出片"
- 任何"素材 → AI 剪辑 → 封面 → 发布"的自动化诉求

## 铁律 0：先定素材授权，再谈技术

| 素材源 | 判定 |
|---|---|
| 自己直播/自己拍摄 | ✅ 主力 |
| 明确开放切片授权的主播（官方切片计划、MCN、蝉选等三方平台） | ✅ 可做，分成常见 10–30% |
| the user 授权 / 公共领域 / 政府公开素材 | ✅ 需自己加价值 |
| 搬运外网博主内容 | ❌ 违法 |

搬运不成立的理由（一次讲清，别只喊"侵权"）：境外作品同等受著作权法保护（对等保护）；**非商用也不豁免**；去水印/加字幕/二次剪辑**不改变**侵权性质；投"转载"标签 ≠ 合法（平台不追≠版权方不追）；有商业属性（激励/带货/分成）升级为严重违法，规模化可入刑。

**风险等级看"官方定性"而不是"有没有被封"：**
- 账号被**销号**或被**中央网信办点名 / 央视起底定性**（如"煽动群体对立"）→ 素材报废，别碰。
- 仅**禁言 / 禁止关注**后解禁、账号主体仍在、仍在直播 → 可谈授权后使用。
- 主播有反复翻车的固定话题区（性别对立 / 明星八卦 / 时政 / 踩国产崇洋）→ 切片时加过滤层跳过这些片段。

## 铁律 1：平台现状必须实测，不要用二手报道下结论

- 用户说"他的切片还在平台上"时，**先跑 `scripts/bili_search.sh <关键词>`** 拿真实播放量与上传日期，再用数据说话；不要拿新闻摘要反驳用户。
- 报道里的"内容被清空"通常只指**其本人账号**，**不等于第三方上传的切片被清** —— 两件事必须分开说，混为一谈会被用户当场纠正。
- 判断素材源值不值得投产，看**新上传切片的播放量**，不看存量爆款：存量 632 万 vs 新发几千～几万 = 限流特征 → **能发 ≠ 能起量**；在限流源上做批量矩阵生产是白干，还吃"账号矩阵"风控。

## 流水线（8 步）

```
①录制 → ②弹幕采集 → ③ASR → ④高光检测 → ⑤剪辑+字幕 → ⑥封面 → ⑦人工复核 → ⑧投稿
```

- **高光检测必须用弹幕信号**：弹幕密度 + 情绪词 + 语义重合（ASR 与弹幕 CJK Jaccard）三信号加权 → 平滑 → 峰值检测。弹幕是观众逐秒投的票，比任何模型推断都准。
- 切点对齐到**字幕词边界 + 镜头边界**（TransNetV2 ONNX，31MB），避免从半个动作开始。
- **默认半自动**：机器做到"待发队列"，人点一下才发。全自动批量发最容易踩风控。
- 加**风险过滤层**：自动丢弃命中高风险话题关键词的片段（针对擦边主播素材必加）。

## 工具选型（优先现成的，不要自己写）

| 工具 | 亮点 | 适合 |
|---|---|---|
| HotClip | 桌面双击即用；弹幕信号（录播姬 .xml / 抖音 .jsonl）；录播监听 7×24；**自带 CLI + MCP，可由 agent 驱动** | 起步首选 |
| bilive | B站录制+弹幕+ASR+切片+投稿一条龙，兼容低配 | 无人值守 |
| Stream-Clipper-Factory | 三信号融合 + 复核工作流 + 反馈学习 | 自动+人工复核 |
| AI-Matrix-Clipper | 一条命令：找爆点→Hook 片头→封面→标题→上传 | 全链路 |
| openclip | 轻量：下载→转录→分析→切片→封面 | 长视频/播客 |

零件：`yt-dlp`（录制/下载）、`blrec`/`bilive`（B站带弹幕）、`faster-whisper large-v3` / `Paraformer`（中文更稳）、`ffmpeg` + `libass`（卡拉OK 逐字字幕）。

## B站投稿约束（会直接导致限流）

- `copyright=2` **必须**配 `source`；**转载投自制**会在播放量 1 万左右触发二审 → 判低创限流。自制用 `copyright=1`。
- 一条稿件改标题/简介/换源 **>2–3 次 → 直接限流**，资料一次到位。
- Web 端多 P 投稿限 **Lv3+ 且粉丝 >1000**，否则走 client 提交接口（client 提交 + Web 上传线路是最优组合）。
- cookie 会过期（抖音约 24h，B站较久），需续期；高并发请求会 412 / 短封 IP，加延时与重试。
- 工具：`biliup-rs`（CLI，扫码/短信/密码登录，支持分P、`--dtime` 定时、封面、`--copyright`/`--source`）、`bilibili-api-python`、`bilibili-toolman`。

## 本地模型（RTX 4080S 16G 可跑）

| 环节 | 模型 | 显存 |
|---|---|---|
| ASR | faster-whisper large-v3 / Paraformer-large | 3–6 G |
| 高光判断 | 云端 LLM（the user 有 DeepSeek 直连，¥0.8–1.5/条）或本地 Qwen3-30B-A3B | 0 / ~18 G |
| 视觉信号 | Qwen3-VL 4B（Ollama）+ FER+ 表情（近零成本） | 6–10 G |
| 镜头分割 | TransNetV2 ONNX | ~0.5 G |
| 封面 | Qwen-Image 2.1 GGUF Q4–Q5 / Flux.1-dev GGUF / SDXL | 8–12 G |

**显存分阶段串行**：ASR 与封面生成不要同时占显存，别和 ComfyUI/Ollama 抢。

## 交付形态（the user's 偏好）

- 方案写成 markdown 落到 `~/.hermes/plans/`，**同时**出一张攻略型 PNG 流程图（深色底、表格化、标出 ✅/⚠️/❌ 三条路线）。
- 分期给路线（一期跑通半自动 → 二期加自动投稿与本地封面 → 三期无人值守 + 数据回流），并明确"开工前需你拍板的 N 件事"。

## 坑

- `scripts/html2png.py` 必须传**绝对路径**（相对路径会拼成 `file://xxx/` 报 `ERR_INVALID_URL`）。
- 生产环境仍以人审为主时，不要承诺"全自动"；把"人点一下"当成正式设计说明，而不是临时妥协。
