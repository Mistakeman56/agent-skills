# 海报 / 启事类图片交付

用户喜欢把结果做成**能打印、能发朋友圈的图**（不只是文字）。寻猫启事、公告、活动通知都走这条。

## 第 1 步：先出可用初版，别干等信息

缺信息时最糟的反应是连问 6 个问题再动手。反过来：**把已经知道的全填上，交付一版带可见空位的
初版**，在同一条消息里列清楚还缺哪几项。用户看到实物才会给出缺的信息，空位本身就是催单据。

已有信息来源：记忆（用户住址、宠物、时间线）、用户刚发的照片（用 vision 读特征）、上文对话。

**唯一能阻断交付的缺项：联系电话。** 启事没有电话等于废纸，这项要单独标出催；其余缺项带空位
先发，补一项就能秒出终版。

## 第 2 步：HTML → Playwright 截图（不要用 PIL 手画）

固定模板 + 参数化脚本：`scripts/make_poster.py <名字> <电话> <照片路径> <特征描述> [天数]`。

用 HTML/CSS 而非 PIL 的理由：flex 布局、圆角、间距、自动换行用 CSS 几行搞定，PIL 要逐行算
坐标；同一个模板改参数就是另一张启事。

**渲染要求：**

```python
page = b.new_page(viewport={"width": 1080, "height": 1600})
page.goto(f"file://{html_path}")
page.screenshot(path=out, full_page=True)   # 必须 full_page
```

- **`full_page=True`** —— 只截视口会把底部联系方式和致谢裁掉，启事直接作废
- **中文字体必须显式点名已安装字体**（`font-family: "Noto Sans CJK SC", sans-serif`），否则
  出豆腐块。先 `fc-list :lang=zh` 确认（本机有 Noto Sans/Serif CJK SC、AR PL UMing）
- **照片用固定高度容器 + `object-fit: cover`** —— 手机随手拍的横竖图直接塞进 `<img>` 会
  拉变形或把整个版面撑长
- 本机图片用 `file://` 绝对路径；HTML 和 PNG 落在技能 `out/` 目录，别放 `/tmp`（易被清）
- 依赖已齐：playwright + 系统 google-chrome + Pillow

**模板变量替换后必须断言检查**，防止变量名写错时静默产出一张废图（曾因 f-string 引用到残留
变量，产出的目标路径变成了一个数字）。

## 第 3 步：发送前必须 vision 自检

用户对交付物要求**视觉逐项检查**（同 Office 文档规则），发之前自己先看一遍：

1. 标题是否醒目、有没有被红框裁切
2. 照片是否完整清晰、**没有拉伸变形或裁掉头脸**
3. 有无文字溢出、重叠、换行错乱
4. 缺项占位是否明显（能看出“待填”而不是误以为已填）
5. 底部致谢 / 提示语是否完整

排版有问题改模板重出，**不要把半成品发出去**。

## 第 4 步：交付

微信渠道用 `MEDIA:/绝对路径/文件名.png` 发原图（中文文件名可以）。同一条消息给：

- **已填清单**（哪些不用再给）
- **待补清单**（哪几项、哪项急）
- 涉及时效（走失、活动截止）补一句当下该做的事

改参数重出图只要几十秒，所以“补一项 → 秒出终版”是可承诺的。

## 坑

1. **别只出纯文字启事** —— 用户要能打印、能转发的图；文字版既不好看也没法张贴。
2. **别在没自检的情况下发图** —— 裁切/拉伸/溢出发出去才发现等于浪费一轮。
3. **别把「缺电话」和其他缺项混在一起** —— 其他空位可以先放着，电话缺了整张作废，单独指出。
4. **已知信息别留空**（如已确认的品种、外貌），空位只留给确实不知道的。
