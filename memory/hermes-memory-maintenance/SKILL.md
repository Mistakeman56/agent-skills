# Hermes 记忆档维护（MEMORY.md / USER.md）

## 何时用
- 用户说"记住这个"、"更新一下记忆"、"我把你改名了 / 以后叫我 X"
- 要成批改条目、要腾空间、要核对有没有被改坏
- 用户说"把你的记忆发出来看看"

落盘位置：`~/.hermes/memories/MEMORY.md`（我的笔记）与 `USER.md`（关于用户），条目以 `§` 分隔。

## 铁律 1：`replace` 是**整条替换**，`old_text` 只用于定位
- `old_text` = 用来**找到那一条**的短子串；`content` = **那一条的新全文**。
- 按"改子串"的直觉只写几个字（`old_text` 取一段、`content` 只写改后的几个字），那条记忆会被**压成这几个字** —— 其余内容静默丢掉，工具仍返回 success。
- 正确姿势：`old_text` 取该条里最独特的一小段，`content` 写**这一条完整的新文本**（含原封不动的部分）。

## 铁律 2：腾空间要在**同一次 batch** 里“缩/删 + 加”一起交
- 一批 operations 原子生效，**字符上限只在全部应用后检查** → 单独 add 会因超限被拒（报 “would be at N/limit”），同批里把几条长条目缩掉就能通过。
- 先算账：要新增 N 字，就先挑最啰嗦的旧条目改写，顺手砍掉 N+10 字。
- 容量参考：MEMORY ~2200、USER ~1375 字符，两条常年在 99%，默认没富余。
- 分工：环境/密码/持仓纪律/称呼这类"是谁、什么状态"进记忆；**一次性操作过程与可复用流程进技能**（记忆每轮都注入，塞多了既超限又稀释信号）。

## 铁律 3：批量改完**读盘核验**
- 工具报 success ≠ 内容没被压坏。改完立刻 `read_file` 两个档核对。
- 发现被压成几个字的条目 → 用**系统提示里注入的那份记忆**逐条恢复（那份就是完整快照），恢复后再读一遍确认。出现这类事故**主动向用户报告已修复**（用户重视“承认 + 一次改完”，不要瞒）。

## 铁律 4：改名 / 改称呼要全档传播
- 用户改称呼（或给我改名）= 在**两个档**里 grep 旧词，逐条 replace 成新词；同样必须写全文（见铁律 1）。
- 改完扫一眼有没有漏网的旧称呼（`grep -n`），一次改干净再回话。

## 铁律 5：把记忆贴给用户看时，凭证打码
- 用户说"把你的记忆发出来看看"→ **逐条编号**输出（他要按编号纠正），但设备密码/API key/admin 口令一律写成 `****`，并告知原文文件路径。
- 结尾列出"我觉得可疑、想请你核的几条"（过期数字、已成交的计划、暂缓中的决定），把纠正成本降到一句话。
