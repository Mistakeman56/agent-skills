## Triggers

- 用户发来一个链接/视频问 **「这个怎么做的？咱们能复刻吗」**
- 要做**浮在真实网页之上**的动画层（生物、粒子、连线、高亮），且**不能改原页面排版**
- 需要让动画的「脚 / 手 / 接触点」精确落在**真实 DOM 元素**上（正文文字、链接词、表格、ISBN 号这类具体词）
- 任何「把参考效果还原成自包含 HTML 作品」的需求

## 交付形状（该用户认这个）

1. **单文件自包含 HTML**（无 CDN 依赖、双击即开），存 `~/.hermes/creative/<名字>/index.html`。
2. **微信交付走视频**：HTML 附件在手机端无法预览 ✗。用 Playwright 录屏 → ffmpeg 转 h264 / `pix_fmt yuv420p` / `+faststart` 的 mp4 → 回复里写 `MEDIA:<绝对路径>`（微信里可内联播放 ✓）。
3. **回复结构固定四段**：① 怎么做的（分层原理，带公式/关键 API）② 验证数据表（真测量出来的数）③ 踩过的坑（诚实列，含没修好的）④「想调什么说一句」。该用户要**原理 + 硬数据**，不要空话 ✗。
4. 主动给**可调旋钮**（数量/线径/透明度/颜色）并说明「说一句就改」。

## 四层结构（照这个搭）

1. **覆盖层**：`<svg>` 用 `position:fixed; inset:0; width:100%; height:100%; pointer-events:none`。页面滚动/缩放只更新 viewBox，**不触碰原 DOM**。
2. **锚点（落脚点）**：`querySelectorAll('p,a,li,h2,td,.reference,.tax')` → 再用 **`Range.getClientRects()`** 取**逐行**小矩形。
   - ✗ 用 `getBoundingClientRect().right` 取元素边缘点 = 脚踩在段落右侧**空白**上（宽段落必翻车）。
   - 每个接触点**只认半径内**（约 1.3× 体长）的锚点，超出就原地不动 —— 远距离目标会把肢体拉成直线 ✗。
3. **两节骨 IK**：躯干 + 每肢 2 骨，余弦定理反解关节 `cosA = (L1² + d² − L2²) / (2·L1·d)`；`d` 先 clamp 到 `L1+L2`；膝盖转向用**叉积定侧**，别写死方向。
   - 骨长要**明显大于静止距离**（例：L1=0.80s / L2=0.88s 对静止距离 ~1.0s）→ 关节弯 40~60° 才看得出来。骨长贴着最大伸展 = 肢体永远是直线 ✗。
4. **步态状态机**：交替四足 —— 每条肢体分「支撑 / 摆动」两相；**支撑相把接触点钉死在世界坐标**（页面滚动时按 scroll 增量换算），摆动相抬起→前伸→落下。躯干匀速漂移即可，接触点会自己跟着走。
   - 自检：任意时刻「已钉住的数量」应约为总肢数一半并**缓慢变化**（如 7→4→3）；长期 0~1 = 速度或相位算错，表现成抽搐 ✗。

## 必须避开的渲染坑

- **`mix-blend-mode: screen` 会把近黑填充整个吃掉**（screen 下深色 ≈ 透明）→ 拆两层：发光元素（肢体/眼/丝线）走 screen 层，**实体（深色躯干）走普通混合层并叠在上面**（顺带获得正确遮挡：肢体从躯干后面穿过 ✓）。
  - 症状识别：**「肢体从一点放射」+ 看不出躯干** = 就是这一条，先查混合模式。
- **细节画在低层会被上层不透明躯干盖住** ✗（DOM 里数得到、画面上看不见）→ 眼睛/口器这类「躯干上的细节」必须画在躯干**之后**的同一层。
- **速度单位**：`y += vy*dt*60` 会把 10px/帧变成 600px/秒 ✗（症状 = 抽搐、接触点永远跟不上）。速度一律 **px/秒**：`y += vy*dt`。
- 躯干要有**两节**（大腹 + 小头胸部）+ 一对附肢才读得出「像生物」；单个椭圆 = 空心气泡 ✗。
- 出界用**反弹**（`v = -|v|`）而不是瞬移回另一侧，否则看起来像抖动。

## 验证协议（别只靠肉眼）

1. Playwright 无头打开 `file://`：监听 `pageerror`（必须 **0**）+ 截全页图。
2. **程序化量指标**（把 JS 注入页面算，不靠目测）：接触点到最近文本框的距离中位数（目标 0~3px）、已钉住数量、接触点 2 秒内位移（证明真在动）、关节角（证明不是直线）。**程序化数字才是说得出口的证据 ✓。**
3. **放大裁切再看图**：`page.screenshot(clip=...)` 把单个对象放大 10~15 倍，再交 `vision_analyze`。整页图里 4px 的眼睛/关节**根本看不见** —— 「眼睛被盖住」「肢体是直线」这类 bug 只有放大才抓得出 ✓（这一步最值钱）。
4. 录屏交付前**再抽一帧**看一遍，确认录到了好画面。

## 反例（一看到就照这个顺序查）

| 现象 | 先查 |
|---|---|
| 肢体从一点放射、躯干看不见 | `mix-blend-mode: screen` 吃掉暗色实体 |
| 接触点踩在空白上 | 锚点取了元素边缘，不是 `Range.getClientRects()` 的逐行框 |
| 抽搐、接触点不换位 | 速度用了 px/帧（`*dt*60`） |
| 肢体是直线、没有关节 | 锚点太远 / 骨长贴着最大伸展 |
| 细节在 DOM 里但看不见 | 画在了被不透明躯干覆盖的低层 |
