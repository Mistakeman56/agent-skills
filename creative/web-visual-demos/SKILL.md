# 网页视觉演示：复刻 → 构建 → 验证 → 交付

适用范围：用户发来视频/截图问「这个怎么做的？咱们能复刻吗」；或要做一个**能动的网页视觉** —— 覆盖层动画、拟物生物、canvas/SVG 特效、跟着页面内容走的装饰。

## 交付物形状（先定死，别边做边改）

- **单文件自包含 HTML**：`~/.hermes/creative/<slug>/index.html` —— 无构建、无 CDN、无依赖，双击即开
- **聊天里别指望用户能预览 HTML**：微信/聊天客户端把 `.html` 当附件下载，手机上打不开 ✗ → **录成 MP4 发**（见「步骤 5」）
- 想让用户手机上真能玩：**提议**挂到他自己的门户（静态文件 + 现成反代 ✓）；**别擅自改生产反代**（该用户有「别给自己修坏了」红线）

## 步骤 1 · 逆向参考片

1. 取件：X/Twitter 用 `api.vxtwitter.com/<user>/status/<id>`（免登录）或 `xurl`；直连抓取常被本机 fake-ip 挡（解析到 `198.18.x` ✗）→ 走本地代理
2. 抽帧：`ffmpeg -ss <t> -i v.mp4 -frames:v 1 frame_<t>.jpg`，取 5–8 帧（0.3 / 2.5 / 5 / 7.5 / 10 / 12.5 / 15.5）
3. `vision_analyze` 逐帧问：这是什么效果、分几层、主体落在哪些元素上、动作节奏 → **先把技术分解写出来，再写代码**
4. 常见分解：覆盖层 + 元素坐标采样 + 逆运动学 + 步态/节奏；算法骨架见 `references/overlay-ik-technique.md`

## 步骤 2 · 构建（四条硬规则）

1. **覆盖层**：`<svg>` `position:fixed; inset:0; pointer-events:none`，z-index 高于正文 —— **绝不改原 DOM 排版**
2. **锚点取逐行文本框**：`Range.getClientRects()`。取元素的 `right`/`bottom` 边缘 = 落在段落右侧空白里 ✗（第一版就这么翻车，脚全踩空）
3. **IK 解关节**：两节骨头用余弦定理 `cosA = (L1² + d² − L2²) / (2·L1·d)`；`d` clamp 到 `L1+L2`；**骨头总长 ≈ 静止距离的 1.6–1.9 倍**才看得到明显膝弯（骨头太短 = 腿是直线）
4. **步态**：支撑相把脚**钉在世界坐标**（不随身体平移），摆动相才抬起/前伸/落脚 —— 身体走、脚留在原地，才叫「爬」

## 步骤 3 · 渲染层的坑（症状都很反直觉）

- **`mix-blend-mode: screen` 下近黑填充 = 完全透明**：深色身体整个消失，而你看到的症状是「腿从一个点放射」「身体没有两节」，根本不会想到是混合模式 ✗ → **拆两层**：加色层（screen：发光腿/丝线）+ 实体层（normal：深色身体），各自一个 `<svg>`
- **后画的在上**：眼睛、螯肢、标记这类必须被看见的小部件要画在**不透明身体之上**；放在下层 = 被盖住 = 视觉复核判「没有眼睛」
- **速度单位是 px/秒**：写 `vy*dt*60` 就是 60 倍速 → 步态退化成抽搐，症状是 `planted ≈ 0`（脚几乎不换位）
- **锚点要限半径**（≤ ~1.35× 体型）：锚点太远时 IK 会把腿拉成**笔直的射线**

## 步骤 4 · 验证（不许只靠眼睛，三件套都要）

- **无头渲染**：Playwright 起 chromium，收 `pageerror`，断言 **0 报错**
- **量可证伪的数字**（用 `scripts/verify_web_demo.py`）：
  - 脚到最近文本框的距离 → 中位应 ≈ 0（这是「真的踩在字上」的唯一证据，肉眼看不出来）
  - 随时间采样的 planted 数 → 应在两者之间交替波动，而不是恒 0（=抽搐）或全踩（=没换步）
  - 膝关节角 / 某只脚两个时刻的位移 → 证明确实有折角、确实在动
- **全页截图 + 主体放大裁切**：`clip=` 主体 bbox 外扩 ~130px + `device_scale_factor=2`，把裁切图交给 `vision_analyze`
  - **放大图才是捉 bug 的依据**：全页尺度下 <10px 的细节会被判「不存在」（眼睛、关节、有没有压在字上全会被误判）
  - 视觉复核**连续几轮重复同一句批评**时，别再继续调几何 → 去找**渲染层**原因（这条抓出过「身体被 screen 吃掉」这个根因 ✓）

## 步骤 5 · 交付

- 录屏：`new_context(record_video_dir=..., record_video_size=1000x1000)` → 关闭 context 落 webm；期间用 `mouse.wheel` 滚动、`mouse.click` 触发交互，让演示带上「滚动后重新踩点」的镜头
- 转 MP4（聊天里内联播放）：
  ```
  ffmpeg -i x.webm -vf scale=1000:1000,fps=30 -c:v libx264 -crf 21 -pix_fmt yuv420p -movflags +faststart demo.mp4
  ```
  15 秒左右 / 1–2MB 最合适 ✓
- 回复里给：`MEDIA:<绝对路径>` + **技术分解** + **验证表格（真实数字）** + **真实踩过的坑（认账）** + 明确的调参入口（数量 / 线径 / 透明度 / 要不要丝线）
- 视觉批评与参考风格冲突时如实说：像「线条偏多、挡正文、颜色刺眼」这类意见，若参考片本来就是这个路子，就说明原因并给可调项，**不假装完美** ✓
